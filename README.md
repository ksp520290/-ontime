# Runtime Board（進行表・タイマー管理コンソール）

Ontime を参考に、サーバー不要・HTML / CSS / Vanilla JavaScript のみで構成した
進行表・タイマー管理ツールです。

## 画面一覧

### 本番モード画面（本番中に使う5画面）
| ファイル             | 役割                                                                 |
| --------------------- | ---------------------------------------------------------------------- |
| `rundown-view.html`  | 進行表（閲覧用・基本タブの内容のみ）。司会はコンパクト表示            |
| `operator.html`      | オペレーター画面。再生制御、押し／巻き表示、メッセージ送信             |
| `timer.html`         | 客席・登壇者向けの全画面タイマー表示                                   |
| `backstage.html`     | バックステージ・楽屋向け表示                                           |
| `technician.html`    | 技術者用。基本／上手／下手／照明／音響タブ                              |

### その他の画面
| ファイル               | 役割                                                       |
| ----------------------- | -------------------------------------------------------------- |
| `index.html`            | ホーム。プロジェクト情報、本番モードのON/OFF、同期設定、書出/読込 |
| `schedule.html`         | 予定表（連携内容メモ・todoリスト）                              |
| `editor.html`           | 進行表エディタ（作成・編集・印刷）。基本/上手/下手/照明/音響タブ |
| `retrospective.html`    | 振り返り。イベント／見出しをクリックして振り返りメモを記入        |

## 本番モードについて

ホーム画面の「本番モード」トグルをONにすると、上記5つの「本番モード画面」以外
（予定表・進行表エディタ・振り返り）はロックされ、開いても編集できない画面が表示されます。
本番前の準備がすべて終わったらONにし、事故防止のため進行表の構成をうっかり変更できない
状態にする、という使い方を想定しています。OFFに戻すにはホーム画面のトグルを操作してください。

## 司会（MC）の自動挿入について

進行表エディタで「＋ イベントを追加」を押すと、追加したイベントの直後に
「司会（つなぎ）」が自動的に挿入されます。司会エントリは：

- キュー番号は採番されません（イベントのみに連番が振られます）。
- 進行表（`rundown-view.html`）や振り返り画面では、キュー欄が「-」、
  タイトルのみのコンパクトな行（通常の半分の高さ）で表示され、
  タイトルをクリックすると副題がアコーディオンで開閉します。
- オペレーター画面・技術者用画面・進行表エディタでは、タイトル／副題・出演／担当・
  メモ・所要時間・開始／終了・削除／並べ替えボタンを含む全項目が常時表示されます。

## 技術者用タブについて

`technician.html`（および `editor.html`）は「基本」（常時ON）に加えて
「上手」「下手」「照明」「音響」タブを複数選択でき、選択したタブに応じて
テーブルに列やコントロールが追加されます。

- **上手**：各行に複数行入力可能な「メモ」列が追加されます。入力中でない行は
  1行だけ表示に折りたたまれ、タップすると展開されます。現在進行中の行は
  常に展開された状態で表示されます。
- **下手**：司会の行にのみ「緞帳」ボタン（ー／上げ／下げ）が表示されます。
- **照明**：「幕間」「アリーナ」「作業灯」のトグルボタンがツールバーに表示され、
  ONの間は背景色が変化して強調表示されます。
- **音響**：「司会」トグルボタン（ONの間背景色が変化）と、各行の「音源」「マイク」
  メモ列（上手のメモと同様の折りたたみ挙動）が追加されます。

## リアルタイム同期について（重要）

このツールは **サーバープロセスを含まない静的なファイル一式** として配布しているため、
自前のWebSocketサーバーやSSE（Server-Sent Events）配信は同梱できません
（それらにはサーバーを常時起動しておく必要があるためです）。そのため、同期は次の
2段階で実現しています。

1. **同一ブラウザ内の複数タブ／ウィンドウ（既定・設定不要）**
   `BroadcastChannel` API を使い、遅延ほぼゼロで自動的に同期します。
   同じPC上で「オペレーター画面」と「客席モニター用タイマー」を別ウィンドウで
   開くような使い方であれば、これだけで十分リアルタイムに同期します。

2. **異なる端末間（別PC・タブレットなど）で同期したい場合 → Firebase Realtime Database**
   ご自身の無料のFirebaseプロジェクトを使うことで、離れた端末同士もほぼリアルタイム
   （目安：1秒未満〜数秒程度）に同期できます。設定手順は以下のとおりです。

   1. https://console.firebase.google.com/ にアクセスし、Googleアカウントで
      新しいプロジェクトを作成します（無料枠で問題ありません）。
   2. 左メニューの「構築」→「Realtime Database」を開き、データベースを作成します
      （リージョンは任意）。
   3. 「ルール」タブで、動作確認中は以下のような簡易ルールにしておくと手軽です
      （本番運用時はより厳格なルールに変更することを推奨します）。
      ```json
      {
        "rules": {
          "runtimeboard": {
            "$room": {
              ".read": true,
              ".write": true
            }
          }
        }
      }
      ```
   4. 左メニューの「プロジェクトの概要」→ 歯車アイコン →「プロジェクトの設定」→
      「マイアプリ」で ウェブアプリ（`</>`アイコン）を追加し、表示される
      `firebaseConfig` オブジェクト（`apiKey` や `databaseURL` を含むJSON）を
      コピーします。
   5. このツールの `index.html`（ホーム画面）の「リアルタイム同期設定」欄に、
      現場ごとに決めた任意の「ルームID」（例: `bunkasai-2026`）と、
      コピーした Firebase Config を貼り付けて「保存して接続」を押します。
   6. 同期させたい他の端末でも、同じURLのファイル一式を開き、同じルームIDと
      Firebase Config を入力すれば、以後はどの端末で操作してもリアルタイムに
      反映されます。

   Firebase を設定しない場合でも、上記1.の同一ブラウザ内同期は常に有効です。

## 押し／巻き（オペレーター画面）

オペレーター画面には、進行が予定よりどれだけ「押している」（遅れている・赤）か
「巻いている」（進んでいる・緑）かを一目で確認できるバッジを追加しています。
所要時間の＋／−調整や、実際の再生時間の超過・巻きを累積して表示します。

## データの取り扱い

- すべてのデータはブラウザの `localStorage` に保存されます。
- Firebaseを設定した場合のみ、その内容がご自身のFirebaseプロジェクトにも送信されます
  （弊社・第三者のサーバーには一切送信されません）。
- ホーム画面からいつでもJSON形式で書き出し・読み込みができます。

## 印刷 / PDF化

`editor.html` の「🖨 印刷」ボタンからブラウザの印刷機能を呼び出せます。
印刷ダイアログの保存先を「PDFに保存」にすることでPDF化できます。
